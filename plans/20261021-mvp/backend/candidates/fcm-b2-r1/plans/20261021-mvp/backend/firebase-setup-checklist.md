# Checklist Firebase cho staging (chỉ FCM)

Ngày 2026-10-21. Backend vẫn Cloudflare Worker + D1, không bật Firestore/Auth. Chưa thực hiện cấu hình hay gửi thử. Các bước 1–2 chặn mọi gửi, 3–5 chặn iOS, 6 chặn web, 7–8 chặn gửi từ Worker; bước 9 đợi backend/client có mã.

1. **Người dùng:** tạo Firebase project cho staging, không cần bật Analytics; ghi tên biến `FCM_PROJECT_ID` cho cấu hình Worker, không dán giá trị/credential vào chat.
2. **Người dùng:** kiểm và bật Firebase Cloud Messaging API (HTTP v1) trong Google Cloud của đúng project; xác nhận FCM Registration API cho web đã bật.
3. **Người dùng:** thêm app iOS với bundle id tạm `com.study.teacherthu` (cần khớp target khi build), tải `GoogleService-Info.plist`, giữ trong thư mục cấu hình riêng ngoài repo công khai; dev thêm vào target/build bằng file local hoặc CI secret file, chỉ commit bản mẫu không có giá trị thật.
4. **Người dùng, cần Apple Developer:** tạo APNs authentication key `.p8` có quyền đúng cho app, giữ private key ngoài repo; lấy Key ID và Team ID, upload key trong Firebase → Project settings → Cloud Messaging → iOS app. Không gửi `.p8` qua chat.
5. **Dev, sau 3–4:** bật Push Notifications entitlement đúng App ID/provisioning; thêm Firebase Messaging SDK vào SwiftUI, nối app delegate/APNs token, xin quyền thông báo và lấy FCM token; thử trên iPhone thật (chưa làm ở bước nền iOS).
6. **Người dùng + dev:** thêm app Web, lấy cấu hình Firebase web và public key của cặp khoá Web Push **của Firebase** ở Cloud Messaging → Web Push certificates (bắt buộc cho FCM web token; đây không phải Web Push VAPID tự gửi đã bị loại); cấu hình các biến `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`, `VITE_FIREBASE_MESSAGING_SENDER_ID`, `VITE_FIREBASE_VAPID_KEY`. Chỉ public config vào client; service account/private VAPID key không vào frontend. Dev cấu hình HTTPS/service worker, kiểm API đăng ký token theo phiên bản SDK (Firebase đang bổ sung FID), thử PWA iPhone đã cài màn hình chính iOS 16.4+.
7. **Người dùng:** tạo service account riêng cho gửi FCM trong đúng project, quyền Firebase Cloud Messaging API Admin (`roles/firebasecloudmessaging.admin`) hoặc custom role hẹp có `cloudmessaging.messages.create`; tạo khoá JSON và giữ ngoài repo, không dùng Owner/Editor chỉ để gửi push.
8. **Người dùng/vận hành, sau 7:** dùng `wrangler secret put FCM_SERVICE_ACCOUNT_JSON --name qlh-staging-api` để nhập JSON bằng stdin an toàn khi Worker staging đã tồn tại; đặt `FCM_PROJECT_ID` trong cấu hình staging. Không đưa JSON vào dòng lệnh, log, chat hay commit; không chạy lệnh production. Xoay/revoke key khi lộ, xoá cache OAuth khi đổi key.
9. **Dev + người dùng, sau các bước tương ứng:** gửi một thông báo thử không có nội dung nhận xét/điểm, xác nhận nhận trên iOS và web, mở đúng con qua API, rồi thử đăng xuất/chuyển tài khoản/thu hồi token; ghi chỉ mã kết quả, CPU và trạng thái, không ghi token/khoá. Hiện **chưa thể xác minh gửi đầu cuối** vì chưa có cấu hình và mã tích hợp.

[Apple/FCM](https://firebase.google.com/docs/cloud-messaging/ios/client), [FCM web](https://firebase.google.com/docs/cloud-messaging/js/client), [HTTP v1 và quyền service account](https://firebase.google.com/docs/cloud-messaging/send/v1-api). Các file cấu hình client không tương đương private key, nhưng bản thật vẫn giữ ngoài repo công khai theo brief; service account JSON và APNs `.p8` luôn là secret.
